But scanners only find the patterns they know. The findings that hurt most in Shopify apps are usually ones a scanner can't see: - A settings save that trusts a `shop` parameter from the browser - A webhook body parsed before its HMAC is checked, so the check proves nothing - A `shop/redact` handler that returns 200 and deletes nothing - An `orders/create` retry that creates the same record twice Those come from reading the code, the way a reviewer would. upgrades: |- Shopify releases a new Admin API version every quarter and supports each one for at least 12 months. When an app calls a version that's no longer supported, Shopify quietly serves the oldest supported one instead, which can change how your app behaves without warning. Every Shopify app audit checks your pinned API version, REST calls, and Shopify libraries. Public apps also face deadlines: expiring offline tokens are required for all public apps from January 1, 2027. If you're behind, the report lays out the path one step at a time, libraries first.
